# Software renderer baseline, 2026-11-02

Step 1 of the GPU renderer plan: the frame time of the software renderer
behind the `render.Renderer` seam (#46), natively and as js/wasm in
headless Chromium. The GPU renderer (go-gfx/webgpu) is to be compared
against these figures by rerunning the same harness.

## Setup

| | |
|---|---|
| Harness | `cmd/quake-bench baseline`, engine commit `fc3c312c775bfb2fb107225ec4ae8595dd9b4f85` (#48), clean clone, built from that commit |
| Machine | Apple M4 Max, 16 cores, 128 GiB, macOS 27.2 (26B123) |
| Go | go1.27.3 darwin/arm64 (native), GOOS=js GOARCH=wasm (browser) |
| Browser | headless Chromium, Chrome for Testing 156.0.8078.4 (`HeadlessChrome/156.0.8078.4`), served with COOP/COEP for the finest timer |
| Assets | **procedural scene** (stub host + synthbsp, `pak: procedural`). No shareware `pak0.pak` is on this machine and the embedded pak is the empty placeholder. |
| Workload | `game.Build` with the demo-orbit camera, fixed 1/60 s step, null display, software renderer through the seam; 500 (320x200) or 200 (1280x800) warm-up frames, then 5000 or 2000 measured frames per round |
| Cores | native `GOMAXPROCS=1`; wasm is single-threaded |
| Rounds | 7 per configuration, interleaved native, browser, native, browser ... |
| Load | 1-minute load (`uptime`) read before and after every round; any round above 8 is discarded and redone. None was: all readings 5.79 to 7.10 (see below) |

Cells are `median (min-max)` over the 7 rounds. Frame work is
Begin-to-End time of one frame; the interval is frame-to-frame wall time
(the loop runs flat out, no vsync). The engine share is the `sim` stage;
the renderer is everything the seam drives (`world`, `models`, `2d`,
`present`).

## Caveats

- The scene is the engine's procedural fallback, not a Quake level: a few
  textured polygons, no monsters, no alias models. The sim stage is the
  stub host's, so the engine / renderer split here says the harness
  attributes time correctly, not what a real level costs. Rerun with
  `--pak <pak0.pak>` (native) for a real level before drawing conclusions
  about the GPU renderer.
- The load was 6 to 7 throughout (the limit is 8), so times carry that
  noise; the spread columns show it. Allocation counts are exact.
- The browser's timer is coarse (about 5 microseconds with COOP/COEP), so
  the 320x200 wasm percentiles are quantised; the 1280x800 table is the
  better wasm reading.
- `wasm` percentiles use the same nearest-rank method as the native ones.

## Reproduce

```sh
GOOS=js GOARCH=wasm go build -o bench.wasm ./cmd/quake-bench
go run ./cmd/quake-bench baseline --rounds 7 --frames 5000 --warmup 500 \
    --wasm bench.wasm --chromium <headless chrome> --profile <durable dir>
go run ./cmd/quake-bench baseline --rounds 7 --frames 2000 --warmup 200 \
    --width 1280 --height 800 --wasm bench.wasm --chromium ... --profile ...
```
