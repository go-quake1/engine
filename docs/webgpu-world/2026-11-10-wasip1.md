# gpuworld on a remote device (wasip1), E1 of engine#88

`render/gpuworld` builds for `(js && wasm) || wasip1`. The three GPU files were
`gpuworld_js.go`, `alias_js.go` and `special_js.go`: a `_js` file name is a
GOOS=js constraint of its own, so they are now `renderer.go`, `alias_gpu.go` and
`special_gpu.go`. `Renderer.Readback` is per platform (`readback_js.go`,
`readback_wasip1.go`).

## What a remote device changes

Read in go-gfx/webgpu v0.18.0 (`remote.go`, `copytexture.go`) and
go-wasmcontainers/gpu (`wasigpu/batchsink/sink.go`):

- `Queue.WriteTexture` returns `ErrRemoteUnsupported`; `Recorder.WriteTexture`
  carries it. The surface atlas is 33 MB, above the host's `MaxFrame` (32 MiB),
  and the sink refuses a single message above a frame. `uploadTexture` therefore
  cuts every texture into bands of whole rows of at most `MaxBandBytes` (8 MiB),
  one Recorder submit per band; `writeBuffer` does the same for buffers.
- There is no `Device.ReadTexture`. `ReadTexture` (package function, used by
  `Renderer.Readback` on wasip1) copies the texture into a MAP_READ buffer with
  `Recorder.CopyTextureToBuffer` (`bytesPerRow` a multiple of 256) and reads it
  with `Recorder.ReadBuffer`, in bands of whole rows that fit the host's 1 MiB
  read window, then drops the padding.

## Tests

`upload_test.go` drives a remote device over a fake host that decodes the stream
(`wire.Decode`), keeps what `WriteTexture` wrote, and answers
`CopyTextureToBuffer` + `ReadBuffer` with the 256-byte padding:

- `TestUploadTextureBands`: a 16 MiB atlas goes up in two submits, none above
  `MaxBandBytes`, and every row is the host's.
- `TestReadTextureDepads`: a 1000 x 2000 texture (pitch 1024, 2 MB padded) comes
  back in two bands, equal to what was written.

Break check: with `bandRows` returning an unbounded row count, 3 of the 3 tests
fail; with the de-padding stride changed from the pitch to the width, 1 fails.

## What is not proved here

The proof that the guest's GPU frame matches the CPU's needs a host that runs the
stream: the wasmcontainers playground (go-wasmcontainers/playground, `TestQuake`)
on go-wasmcontainers/gpu. Both pin go-gfx/webgpu v0.15.0, which refuses a render
module with loops (E2) and does not carry `CopyTextureToBuffer`; no gpu release
on v0.18.0 exists yet. Also note that "equal to the CPU's frame" cannot be a hash
equality on a real GPU: `cmd/quake-worldcheck` measures 45 of 1,024,000 pixels
different on the 16 views (see the surfcache page, v0.9.0), so the check is the
worldcheck's tolerance, not a SHA-256.
