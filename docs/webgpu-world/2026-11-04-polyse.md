# d_polyse.c: the fixed-point edge walk for alias models, 2026-11-04

Step 6, item 2. The engine drew alias triangles with its own float scanline
fill and a plane through the vertex lights. It now runs Quake's rasteriser,
and the GPU shader reproduces it pixel for pixel.

## What was ported (`render/polyse.go`, `render/alias_bbox.go`)

- `PolysetDrawTriangle`: D_DrawNonSubdiv's body, a literal port of the walk
  (span packages, error term, the `ubasestep < 0` light bias, the second left
  segment that restarts with the fractions of `s` and `t` dropped).
- `PolysetDrawSubdivTriangle`, `PolysetDrawFinalVerts`: the recursive drawer
  and the vertex points that a model that is whole in the view and farther
  than `r_aliastransition + size * r_resfudge` takes (`AliasClassify`).
- `DrawAliasInterpQuake` projects to integers, applies the bounding-box
  test, and draws with them; the engine's `game` and `runner` loops use it.
- Not ported, and kept as the engine's own: the z buffer (entities are drawn
  with no depth test, so the span drawers' test is always true); the clipping
  of triangles that cross the near plane (`r_aclip.c`: they are dropped);
  pixels are clipped to the frame; the colormap row is clamped to 63.

**A defect found by the port.** The engine's earlier alias paths drew the
triangles that `d_xdenom >= 0` culls: models were drawn inside out (from
behind a soldier the shaded view showed his face). With Quake's rule the same
camera shows his back. The old tests had pinned the old winding; a model wound
the other way (`quakeFrontTri`) now stands for the front face.

## Pinned tests (`render/polyse_test.go`, `alias_bbox_test.go`)

- `TestFloorDivModIsAdivtab`: all 1,024 entries of `adivtab.h`, parsed from
  the reference tree, against `floorDivMod` (the table is the floor quotient
  and remainder, with 0 0 for a zero denominator).
- `TestPolysetEdgeTableIndex`: one triangle for each of the twelve tables,
  worked from `D_PolysetSetEdgeTable`.
- `TestPolysetFlatTopTriangle`: a flat-top triangle worked by hand (rows
  0..3 cover x 0..7, 1..6, 2..5, 3..4; the gradients 0, 256, 65536, 0, 0,
  65536 and `a_ststepxwhole` 1; every pixel's texel and colormap row).
- `TestPolysetSeamFixup`, `TestPolysetSubdivTriangleAndFinalVerts` (the
  recursion worked by hand for (0,0), (2,0), (0,2): midpoints (1,0), (0,1)).
- `TestPolysetWalkIsItsClosedForm`: the stepped walk against a derivation, on
  3,000 random triangles (more than 100,000 pixels). The error term of
  `D_PolysetScanLeftEdge` gives column `top + ceil(j dx / dy)` on row `j`
  of an edge; the skin position and the light are the row step plus the column
  step times the columns moved, exactly. The GPU shader is written from that
  form, so the test is the bridge between the source and the shader.
- `TestAliasCheckBBox`: nine boxes (near, far, a large model size, clipped,
  rejected on each side, behind, across the near plane), worked from
  `R_AliasCheckBBox` (transition 229.4, fudge 114.7 at 320 x 200).

## GPU

`render/gpuworld/alias.go`: the vertex shader builds the triangle's three
final vertices (the same float operations in the same order: no fused
multiply-add is requested, and none was needed in practice), drops it at
`z < 5` or `d_xdenom >= 0`, and covers the bounding box of the pixels the
walk can reach with one oversized right triangle. The fragment shader holds
the twelve edge tables, finds the row's left and right column in integers,
recomputes `D_PolysetCalcGradients` from the three vertices, and returns
`acolormap[texel + (light & 0xFF00)]`. It does not reproduce the recursive
drawer of far models.

## Acceptance

16 fixed e1m1 alias views, 320 x 200, Apple GPU (`apple metal-3`), Chrome for
Testing 156. **Stated tolerance, before the first measurement: 3 %
unexplained over the alias region** (unchanged from steps 4 and 5).

| | region px | differ | unexplained |
|---|---|---|---|
| step 6 item 1 (float scanline, plane light) | 48,514 | 0.21 % | 0.10 % |
| **edge walk, all entities** | 49,612 | 1.47 % | **0.75 %** (370 px), against 3 % |
| **far entities left out of both sides (`--noFar`)** | 48,981 | **0.25 %** | **0.03 %** (13 px) |
| every skin one flat colour | 50,833 | 0.75 % | 0.27 % |
| flat light | 50,607 | 1.40 % | 0.69 % |
| no interpolation | 49,564 | 1.50 % | 0.76 % |
| no view weapon | 38,398 | 1.70 % | 0.96 % |
| constant light 76 on both sides | 49,978 | 1.44 % | 0.76 % |

The 1.2 % that separates the two top rows is the far entities: the reference
draws them as points (recursive subdivision) and the GPU fills them, the
largest differences being views 5 to 7 (6 % of their pixels). Without them
13 pixels in 48,981 differ beyond a one-pixel shift.

Planted negatives, all failing: skins shifted by 16 (90.21 % unexplained);
the GPU lit at the old constant (56.69 %); **the shader taking the floor
where the error term gives the ceiling for the edge columns
(`TestWrongWalkFails`): 7.67 % unexplained, 18.63 % differing**.
